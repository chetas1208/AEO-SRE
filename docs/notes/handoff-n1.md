# N1 handoff: Neo4j infrastructure + schema

## Interface (import from `app.graph`)
- `get_graph_client() -> GraphClient` (one long-lived async driver per process; lazily created, rebuilt if the event loop changes). `close_graph_client()`, `startup_graph()` (never raises; returns state).
- `await client.run_read(query, params=None, *, timeout=None) -> list[dict]`; `run_write(...)` (managed tx, retried on transient errors only, so statements must be idempotent MERGEs); `run_write_batch([(query, params), ...], *, timeout=None)` = ONE atomic transaction, returns a result list per statement.
- Org scoping: `require_org(org_id)`, `org_params(org_id, params)`, `client.scoped_read/scoped_write(org_id, query, params)`. Scoped calls raise `OrganizationScopeError` if organization_id is missing/blank OR the Cypher does not reference `$organization_id`. Every query function must use these.
- Errors (all scrubbed of credentials): `GraphUnavailable` (base for outage) with subclasses `GraphNotConfigured`, `GraphAuthFailed`, `GraphTimeout`; `GraphQueryError` (server rejected the query; not an outage; `.code`); `OrganizationScopeError`; base `GraphError`. Each outage error has `.state` (NOT_CONFIGURED|DEGRADED|AUTH_FAILED).
- `await client.health(force=False) -> {state, latency_ms, error, database, enabled}` (cached `NEO4J_HEALTH_CACHE_S`=15s); `await client.capabilities()` (cached once connected).
- Schema: `SCHEMA_VERSION=1`, `ensure_schema(client)` (idempotent; returns counts + `complete`), `describe_schema`, `merge_node(label, org_id, node_id, props) -> (cypher, params)` (label allowlist `NODE_IDS`; MERGE key is ONLY the business id; `organization_id` and `app="profound-change-guard"` are SET on every node; callers cannot override them), `node_props`, `clear_application_graph(client, confirm="DELETE-APPLICATION-GRAPH", batch_size=5000)` (deletes ONLY `app="profound-change-guard"` nodes in batches; refuses `system` db). Relationships are NOT constrained (add via MERGE with both endpoints matched by business id and `$organization_id`).
- Settings (root .env): `NEO4J_ENABLED` (unset = on iff URI and password present; false forces off), `NEO4J_URI/USERNAME/PASSWORD/DATABASE`, `NEO4J_GDS_ENABLED=false`, `NEO4J_AURA_API_CLIENT_ID/SECRET`, `NEO4J_CONNECT_TIMEOUT_S=5`, `NEO4J_ACQUISITION_TIMEOUT_S=5`, `NEO4J_QUERY_TIMEOUT_S=10` (server-side tx timeout + client backstop), `NEO4J_MAX_POOL_SIZE=20`, `NEO4J_MAX_RETRY_TIME_S=5`, `NEO4J_HEALTH_CACHE_S=15`. `settings.neo4j_active` is the single on/off check.
- Wiring: `/api/health` gains `neo4j_state` (never degrades `status`); `/api/system/capabilities` gains a `graph` block (state, latency, database, version, edition, gds/aura info; never affects `overall`). API lifespan and arq worker startup call `startup_graph()` (never raises) and close the driver on shutdown. Log redaction now covers `neo4j_password`, the Aura secret and `neo4j://user:pass@` userinfo.
- Tests: `tests/conftest.py` blanks NEO4J_* so unit tests never touch Aura unless `NEO4J_LIVE_TESTS=1`.
- Driver gotcha for N2/N3: `tx.run` rejects `neo4j.Query` objects; per-query timeouts go through `@unit_of_work(timeout=...)` (already done in the client).
