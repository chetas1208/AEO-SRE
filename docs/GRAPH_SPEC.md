# Event-to-Outcome Graph + Graph-Aware Control Policy (binding spec)

Goal: turn events, agent actions, ChangeSets, conflicts, decisions, experiments and outcomes into a **temporal provenance graph in Neo4j Aura**, and use graph-derived features to improve the Change Guard control policy. Not a rewrite; not incrementality; GitHub not involved.

## Architectural rules (non-negotiable)
- **PostgreSQL = system of record** (transactions, idempotency, state machines, approval, experiments, reward, policy versions). **Neo4j = rebuildable projection / system of relationships** (lineage, provenance, contention, similarity, graph features). Neo4j is never required for approval, activation, verification, reward or any state transition.
- Neo4j down/stale/misconfigured ⇒ Postgres keeps working; graph health = `NOT_CONFIGURED | READY | DEGRADED | AUTH_FAILED`; overall API stays healthy; policy falls back to the deterministic BaselinePolicy when graph is unavailable or stale (`graph_context_stale`).
- Write Postgres first, project to Neo4j after commit via a Postgres **outbox** (`graph_outbox`: id, event_type, aggregate_type, aggregate_id, payload JSON, schema_version, created_at, processed_at, attempts, last_error). No Kafka. Projection is idempotent (`MERGE` on business ids = Postgres UUIDs / event ids; **never Neo4j internal ids**). Checkpointing + `make graph-replay`/`graph-rebuild` (confirmation/env guard; clears ONLY the application graph — dedicated database if the plan supports it, else property `app="profound-change-guard"` on every node) + `make graph-audit` (read-only Postgres↔Neo4j count/id reconciliation).
- Every node carries `organization_id` and `app`; **all queries are scoped by organization**; Cypher is parameterized (no string interpolation of user input; no arbitrary-Cypher API); traversals bounded (1–4 hops) with query timeouts.
- Browser never talks to Neo4j; Nuxt → FastAPI → graph service → Neo4j. No credentials in `NUXT_PUBLIC_*`; never print/log secrets.
- Provenance-first, not causal fiction: use `TRIGGERED_BY`, `DERIVED_FROM`, `BASED_ON`, `FOLLOWED_BY`, `ASSOCIATED_WITH`; do NOT create `CAUSED_BY` from temporal order alone. No giant global `NEXT` chain: `NEXT` only within a correlation/run/change lifecycle.
- LIVE data must preserve real Profound identifiers (`profound_agent_id`, `profound_run_id`, project) and never invent them; every event has `source` = PROFOUND | CHANGE_GUARD | HUMAN | SYSTEM and `source_mode` (LIVE | SIMULATED | FIXTURE | TEST).
- Fixture Experiment 1 (EXP-0001) is read-only: it may be projected, never verified/rewarded/altered.

## Configuration (root .env only)
`NEO4J_ENABLED`, `NEO4J_URI`, `NEO4J_USERNAME`, `NEO4J_PASSWORD`, `NEO4J_DATABASE` (already set for the hosted Aura instance: URI `neo4j+s://e528bc40.databases.neo4j.io`, database `e528bc40`; the instance is empty, Aura 5.27). Optional `NEO4J_GDS_ENABLED=false`, `NEO4J_AURA_API_CLIENT_ID/SECRET` (unset). Detect capabilities (AuraDB only vs Graph Analytics vs GDS) at runtime; product must work on plain AuraDB; algorithms have Python fallbacks.

## Graph model (only real domain objects)
Nodes: Organization, Agent, AgentRun, Event, ChangeSet, Target, Claim, PromptCluster, Conflict, Decision, Approval, Experiment, Observation, Outcome, PolicyDecision, PolicyVersion (+ Incident/Intervention only if they exist as real linked objects). Event types: CHANGE_PROPOSED, TARGET_RESOLVED, CLAIMS_EXTRACTED, CONFLICT_DETECTED, DECISION_CREATED, APPROVAL_GRANTED, CHANGE_EXECUTED, EXPERIMENT_STARTED, OBSERVATION_RECORDED, OUTCOME_MEASURED, REWARD_CREATED, POLICY_UPDATED. Event requires event_id, event_type, occurred_at, recorded_at, source, source_mode, correlation_id (+ agent_run_id / incident_id / changeset_id / experiment_id where relevant). Relationships (reconcile with actual domain): STARTED, EMITTED, PROPOSED, MODIFIES, ALTERS, ABOUT, AFFECTS, CONFLICTS_WITH, INVOLVES, PROTECTS, DECIDES_ON, BASED_ON, APPROVES, EXECUTED_AS, MEASURES, OBSERVED, PRODUCED, SELECTED, USED, TRIGGERED_BY, DERIVED_FROM, FOLLOWED_BY, ASSOCIATED_WITH, NEXT (scoped). Uniqueness constraints on every business id; indexes only on hot properties (occurred_at, organization_id, status, event_type, decision).

## Questions the graph must answer (deterministic, no LLM required)
1. Why was this change blocked/delayed? (ChangeSet ← DECIDES_ON ← Decision → BASED_ON → Conflict → INVOLVES/PROTECTS → Experiment → MEASURES → Target ← MODIFIES ← ChangeSet) with a deterministic path-to-text explanation. 2. Which event led to this output (AgentRun → Event → ChangeSet → Conflict → Decision → Approval → Execution → Observation → Outcome). 3. Have we seen a similar situation (agent type, action type, target type, claim types, conflict type, experiment overlap, prompt cluster, decision) and what were the outcomes. 4. Which agents repeatedly collide (pair, count, types, targets). 5. High-contention targets (changes, agents, conflicts, protected experiments). 6. Canonical claims repeatedly contradicted. 7. Which control decisions historically worked in similar contexts (feeds the policy).
Every statement shown to users must correspond to a real node/edge/event/persisted feature.

## Graph features (`graph_context_v1`; explicit, interpretable; persisted with policy decisions)
target_degree, target_recent_change_count, target_unique_agent_count, target_active_experiment_count, changeset_conflict_degree, duplicate_neighbor_count, canonical_conflict_count, prompt_overlap_count, agent_recent_conflict_rate, agent_target_history_count, shortest_path_to_active_experiment, protected_targets_touched, dependency_depth, pending_predecessor_count, historical_similar_context_count, historical_allow_rate, historical_block_rate, historical_review_rate; temporal: seconds_since_last_target_change, changes_on_target_last_1h/24h, agent_changes_last_1h, conflicts_last_24h. Persist per policy decision: graph_feature_version, graph_feature_vector, graph_snapshot_time, graph_context_hash (never recompute history later and pretend it was the original context). Feature cache with computed_at/feature_version/context_hash; expensive algorithms (PageRank, degree, community, node similarity, FastRP) only via periodic jobs and only if they improve held-out evaluation; GDS optional.

## Policy (no PPO/DQN/GNN-RL; contextual bandit only)
Pipeline: ChangeSet → deterministic safety engine (Change Guard rules: canonical hard contradiction ⇒ BLOCK/REVIEW only; protected-target collision ⇒ DELAY/REVIEW only; invalid digest ⇒ BLOCK) → eligible actions (ALLOW|MERGE|DELAY|REQUIRE_REVIEW|BLOCK) → graph+domain feature encoder → contextual bandit → recommendation → human/execution. The learner chooses only among eligible actions; hard rules always win. Keep current rule policy as `BaselinePolicy` (never deleted). Implement `GraphLinUCB` (LinUCB + graph context + action mask + versioned feature schema `graph_context_v1`); evaluate `GraphLinTS` and LinUCB-without-graph; ship only one active candidate. Study (do not copy) fidelity/mabwiser (Apache-2.0, LinUCB/LinTS/partial_fit; prefer depending on it or a small independent adapter), VowpalWabbit/vowpal_wabbit + learn_to_pick (future, high volume), VowpalWabbit/coba (offline evaluation) — inspect licenses before any incorporation; record in THIRD_PARTY.md/research notes only if a dependency is actually added. **Shadow mode first**: BaselinePolicy is active; GraphBanditPolicy runs in shadow, recording baseline decision, bandit recommendation, scores, eligible actions; graduation only after minimum evaluated samples, zero safety-mask violations, acceptable override rate and offline evaluation pass; human approval always remains. Graph unavailable or stale ⇒ BaselinePolicy.
Reward (control-plane quality, not incrementality; weights in versioned config): +1 human accepted and downstream state stayed valid; +0.5 REVIEW correctly escalated ambiguous conflict; 0 insufficient/no outcome (no update); −0.5 human overrode; −1 allowed a conflict that later caused invalid state; extra optional components (duplicate work prevented, contamination prevented, manual-review burden, delay cost, false-block penalty). Learn only from meaningful feedback (never views/hovers/agent-started). Delayed reward supported (decision at t0, outcome at t+n, persisted linkage). Human override stored as separate feedback dimensions (policy recommendation, human decision, reason, final execution, eventual outcome); disagreement is not automatically a policy error. Policy versions immutable (algorithm, feature schema, hyperparameters, training event count, parent, created_at); history never mutated. Explanations list selected action, eligible alternatives, policy score, important graph features, similar historical contexts — no meaningless "AI confidence"; only data-supported statements.
Evaluation (`backend/app/evals_control_policy/` + `make policy-eval`): Baseline vs LinUCB(no graph) vs GraphLinUCB vs GraphLinTS; metrics: agreement with reviewed labels, unsafe action rate, override rate, false block/allow rates, review rate, cumulative reward, regret (simulation only). Graph ablation (domain-only vs domain+graph): if graph features do not help, say so and keep the learner shadow-only. Synthetic/replay data must be labelled; never call synthetic training "real learned intelligence". Do not claim a novel RL algorithm: the contribution is graph-derived operational context + marketing-agent conflict domain + safe action masking + online contextual learning.

## API / UI
`GET /api/graph/changes/{id}/lineage`, `/changes/{id}/context`, `/experiments/{id}/lineage`, `/agents/{id}/conflicts`, plus contention/claims summaries; normalized `{nodes, edges, focus_id, generated_at}` for the existing 3D topology (frontend knows no Cypher); SSE event when the projector processes new events; time filter (last hour/24h/7d); path highlight (click Decision → Agent→Run→Event→Change→Conflict→Decision highlighted, others dim; outcome path Decision→Execution→Observation→Outcome→Policy update); small policy panel (version, recommendation, graph features, historical neighbors) — not 3D. Existing design language; no new tab.
